# 交互组件运动碰撞

`Dream Rotatable` 和 `Dream Translatable` 的详情面板中各有一个 **可转动/可平移 → 碰撞 → 运动考虑碰撞** 开关。默认关闭，已有机关保持原来的无碰撞运动。开关只影响当前组件的运动；转动和平移可以分别配置。

## 行为

- 开启后，每次交互从当前世界姿态开始逐帧前进。完整步长可通过时停在目标姿态。
- 任一碰撞体在本次运动途中受到阻挡，物体先走到障碍前，再沿已走过的路径回弹；结束后位置、角度和逻辑平移坐标都恢复到交互前。回弹期间新的交互会被忽略。
- 动画时长为 0 时仍检测整段路径。若被阻挡，立即保持原姿态；不会跳过碰撞检测或停在半途。
- 平移使用碰撞体扫掠；转动的每帧角度继续细分，并检查每段的扫掠及末端重叠。UE 原生的 `bSweep` 不检查旋转扫过的体积，因此转动仍依赖子步精度。子步限制为最多 2°，并按最远碰撞点的半径收紧到约 2 cm 弧长。

## 关卡配置

1. 被交互 Actor 的碰撞应保持启用，移动件上的网格或碰撞组件须启用 **Query** 碰撞。无碰撞的 SceneComponent 可以作为根；挂在根下的多个碰撞组件都会参与检查。
2. 障碍物与移动件的碰撞响应必须互相为 **Block**。仅设置 Visibility 射线阻挡、仅启用 Overlap 或只有可视网格而没有简单碰撞形状，都不足以阻止运动。
3. 机关和参与运动的碰撞组件需允许移动（Movable）。调试时可用 `dream.DebugPivots 1` 查看枢轴、旋转轴和平移范围。

旋转子步是离散检测：极薄且小于子步弧长的障碍，或没有简单碰撞的复杂网格，仍可能需要更合适的碰撞盒/凸体才能稳定阻挡。回弹回到本次交互的起点；如果其他系统同时强制移动同一个 Actor，两个系统仍需自行协调控制权。
